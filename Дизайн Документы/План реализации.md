# План реализации PlayableSandQuest

Документ фиксирует техническую архитектуру реализации по `Основное тз.md`.

## Главный принцип

Все игровые связи должны быть заданы через префабы и сцену: ссылки на игрока, камеры, магазины, хранилища, маршруты, точки очереди, стрелки, ресурсы и VFX выставляются в Inspector. Компоненты не должны молча искать критичные объекты в рантайме и подставлять fallback-объекты.

## Модули

### Core

- `GameSignals` — простые события без зависимости от конкретной сцены.
- `RequiredReference` — утилита для явной проверки обязательных ссылок.

### Input

- `FloatingJoystick` — экранный джойстик. Появляется в месте тапа, база не двигается до отпускания.

### Player

- `PlayerController` — движение по плоскости XZ, поворот, блокировка движения при достижении лимита шланга.
- `PlayerInventory` — хранение количества ресурсов и визуальные stack roots.
- `PlayerAnimationController` — переключение idle/walk/vacuum-hold состояний через Animation/AnimationController.

### Camera

- `AdaptiveCameraFollower` — следование за игроком под постоянным углом, дистанция зависит от aspect ratio.

### Interaction

- `Interactor` — trigger-зона с событиями входа/выхода/нахождения.
- `StorageInteractor` — хранилище нескольких стопок одного типа.
- `ShopInteractor` — магазин с ценой, прогрессом заполнения и callback покупки.

### Items

- `ItemType` — типы ресурсов: руда, слитки, деньги.
- `ItemStackView` — визуальная стопка предметов.
- `ItemFlyService` — перелёты предметов с tween-анимацией.

### Vacuum

- `VacuumSystem` — TubeHead, TubePart-сегменты, ограничение длины, мигание красным.
- `VacuumCollectProbe` — зона сбора песка/руды на голове пылесоса.

### Sand

- `SandField` — lightweight-grid маска песка. Визуально песок остаётся единым полем, но собранные ячейки скрываются/деактивируются.
- `SandCollectableOre` — руда в песке, засасывается в пылесос и превращается в предмет у игрока.

### CartQueue

- `CartQueueController` — бесконечная очередь орков с телегами.
- `CartUnit` — конкретная телега/орк, принимает золото и уходит по маршруту.

### Hints

- `HintController` — управляет 2D стрелкой в 3D через RenderRoot2D и 3D стрелкой над целью.
- `HintTarget` — точка подсказки на объекте.

### Flow

- `GameFlowController` — state machine playable: песок → обменник → хранилище → магазин → два апгрейда → конвейер → визуальные магазины → packshot.

### Packshot

- `PackshotController` — финальный экран и переход в store.

## Порядок внедрения

1. Документация и журнал работ.
2. Базовые компоненты ввода, движения, камеры.
3. Интеракторы, инвентарь, стопки, перелёты предметов.
4. Пылесос: TubeHead, сегменты, лимит, мигание.
5. Песочное поле и руда.
6. Очередь телег и обмен.
7. Подсказки и игровой flow.
8. Packshot/CTA.
9. Настройка префабов и сцены.
10. Проверка playable-сценария и оптимизация.

## Оптимизация

- Не использовать сетевые загрузки.
- Не создавать тяжёлый runtime mesh boolean для песка.
- Для песка использовать заранее подготовленные ячейки/маску.
- Переиспользовать готовые префабы и root-ноды вместо постоянного создания мусора.
- Не делать автоматические fallback-поиски важных объектов.
- Все ресурсы, маршруты и цели подсказок задавать через Inspector.
